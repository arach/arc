# design-sync notes

## First sync — scope (2026-06-30)
- **In scope:** `ArcDiagram` (2D player), `ArcDiagramIsometric` (3D isometric player), `LandingPage` (marketing page template — user explicitly asked to include it).
- **Out of scope:** `DiagramEditor` / `DiagramCanvas` (heavy interactive editor app — previews poorly as a card), and all non-visual exports (EditorProvider/hooks, themes utils, autoLayout, asciiRenderer, isometric math, sessionStorage, yamlConfig, vanilla renderers, types).

## Brand / tokens source
- Marketing brand tokens live in `src/landing.css` under `.arc-landing` (`--arc-*`: ink/paper/card/border + accents orange `#f07c4f`, teal `#1f7a65`, blue `#2e5fa5`, gold `#d09c36`).
- Fonts: Fraunces (serif display) + Space Grotesk (body), loaded via Google Fonts @import in `landing.css`; JetBrains/SF Mono for code.
- App-wide radius scale recently reduced ("less rounded / more technical") via Tailwind `@theme` tokens in `src/index.css` and halved `border-radius` in `landing.css`.

## Decisions (first sync)
- **Render check:** Playwright + Chromium installed in `.ds-sync/` (user opted in). Browser caches were a disk problem — machine ran out of space mid-run; reclaimed `~/.bun/install/cache` + `~/.cache/puppeteer` (~3.5GB). Disk stays tight.
- **Landing page = brand only** (user choice). NOT shipped as a component. Its `--arc-*` palette + Fraunces/Space Grotesk fonts are exposed at `:root` via `.design-sync/arc-ds.head.css` so the design agent builds Arc-branded surfaces; documented in the conventions header.

## CSS strategy (important for re-sync)
- Arc components are **Tailwind-dependent** (utility classes incl. dynamic theme classes like `text-zinc-100`). The published lib ships NO CSS, so `cfg.cssEntry` is a generated, committed stylesheet:
  - `arc-ds.head.css` (committed) = remote font @imports + `:root` brand tokens.
  - `arc-ds.tw.css` (regenerated by `buildCmd` via `@tailwindcss/cli@4 -i src/index.css`) = compiled Tailwind utilities + `@theme` tokens.
  - `buildCmd` cats head+tw → `arc-ds.css` (the cssEntry). Single self-contained file (converter does NOT follow nested relative @imports).
- `.d.ts` discovery: `rollupTypes:true` makes `lib/index.d.ts` a single file with dangling re-exports → `[ZERO_MATCH]`. Worked around with `componentSrcMap` pinning the two renderers to their `src/*.tsx`.

## Known render warns (expected — don't chase on re-sync)
- `[FONT_REMOTE]` for "JetBrains Mono" + "Space Grotesk" — intentional; shipped as remote @imports via arc-ds.head.css.
- `[GRID_OVERFLOW]` was resolved by `overrides.{ArcDiagram,ArcDiagramIsometric}.cardMode = "column"` (diagrams are wide). Cards render one story per row.

## Re-sync risks (watch-list)
- **Generated cssEntry**: `arc-ds.css` / `arc-ds.tw.css` are produced by `buildCmd` (`@tailwindcss/cli@4` via `bunx`, network). If Tailwind utilities used by the components change, the CSS must be regenerated (buildCmd does it). `arc-ds.head.css` is the only hand-authored CSS input — keep it committed.
- **dtsPropsFor is hand-maintained**: `ArcDiagram` / `ArcDiagramIsometric` prop bodies in config.json mirror the source interfaces (`src/components/ArcDiagram.tsx` ~L557, `src/iso/ArcDiagram.tsx` ~L99). The `lib/index.d.ts` rollup loses real prop bodies (`[ZERO_MATCH]` / empty props), so auto-extraction can't replace these — if the component props change, update `dtsPropsFor` by hand.
- **guidelines/** currently includes some internal planning docs (PROMPT_IMPROVEMENT_PLAN.md, DEWEY_EXTRACTION.md) via the default `guidelinesGlob`. Consider narrowing `guidelinesGlob` if those shouldn't reach the design agent.
- **Landing page**: represented as brand-only (tokens/fonts). If the user later wants the LandingPage component itself, build a design-sync-only entry that re-exports it (don't pollute the published `src/index.ts`).

## Toolchain
- Package manager: **bun** (migrated from pnpm; `bun.lock`, isolated linker via `bunfig.toml`). Use `bun install --frozen-lockfile`.
- `LandingPage` is NOT a published export (`src/index.ts`) — it's an internal app component; must be added to the converter's component map explicitly to sync it.

## Second sync — app pages mapped (2026-06-30)
Mapped two app-internal pages as cards for design iteration: **`LandingPage`** (homepage) and **`DiagramStudio`** (the editor/working page).
- **Mechanism — `src/design-sync-extra.tsx`** (a NEW ds-only build entry, wired via `cfg.extraEntries`): re-exports the two pages as no-prop, card-renderable components. Keeps `src/index.ts` clean.
  - `LandingPage` = real `components/LandingPage` wrapped in `MemoryRouter` (for its `<Link>`s) + no-op `onLaunchEditor`.
  - `DiagramStudio` = real `components/editor/DiagramEditor` (self-wraps `EditorProvider`, is `h-screen`, defaults to a built-in `sampleDiagram`); only needs `isDark`/`onToggleTheme` stubbed — no router needed.
- **CSS fix (critical):** `buildCmd` now also cats `src/landing.css` into `arc-ds.css` — the 137 `.arc-*` homepage rules weren't in the bundle before (landing was "brand-only"). This also pulled the `index.css` `@theme` radius tokens into the shipped CSS, so the whole DS now reflects the "less rounded" pass. Editor uses Tailwind utilities already in the scan — no extra CSS needed.
- **Config:** both pinned in `componentSrcMap` → `src/design-sync-extra.tsx`; hand-written `dtsPropsFor` (no props); `overrides` set card viewport — `LandingPage` `column`/`1280x900`, `DiagramStudio` `single`/`1320x860`.
- **Previews** authored at `.design-sync/previews/{LandingPage,DiagramStudio}.tsx` (import the wrapper by relative path; story-imports Rule 2 redirects to `window.Arc.*`).
- Both render-checked (Playwright) before push; validate clean (4/4). The old "editor previews poorly as a card" worry did NOT hold — the studio renders the full shell + sample diagram fine.
- **Re-sync watch:** `DiagramEditor`/`DiagramCanvas` stay `null` in `componentSrcMap` (excluded as raw exports) — the studio is mapped via the `DiagramStudio` wrapper instead. Don't un-null them.
